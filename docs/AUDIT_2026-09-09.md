# GPU eQTL correctness, performance, and dependency audit

This is the initial audit record. The subsequent [REML/SKAT implementation
follow-up](REML_SKAT_FOLLOWUP_2026-09-09.md) supersedes its unsupported-model and
remaining-SKAT-fallback conclusions.

Baseline: `218b7b17d718c9c8bff3e3611d05d1e1c277775b` (`master`). Audit date:
2026-09-09. Changes are local; this audit does not publish a release.

## Decision

Keep GPU eQTL's current blocked association engine. Consider JLinAlg for a
new, explicitly selected fitted mixed-model/null-model layer. Do not replace
the whole engine or all rare-variant statistics with JLinAlg at present.

This investigation found and fixed actual numerical and execution defects and
measured substantial improvements in the tested workloads. It also found an
important limitation that remains: SKAT's reported moment-matched fallback is
not an accurate general substitute for its quadratic-form distribution.
Passing the regression suite is not an unconditional certification of every
spectrum, cohort, sample size, missingness pattern, or tail probability.

## What the repository actually implements

| Requested area | Baseline implementation | Audit conclusion |
|---|---|---|
| Fixed effects | CPU QR/rank checks; CUDA/OpenCL/native CPU/Java projection and association; resident and streamed matrices; exact trait-pattern deletion | Supported. Existing regression coverage plus independent R checks pass after changes. Small CPU preparation/products were over-threaded. |
| Mixed effects | Cohort-specific fixed designs and supplied covariance/compound-symmetry whitening | This is GLS conditional on a specified covariance shape. It does not fit variance components. Corrected an additional, invalid centering step after whitening. |
| Pedigree | `--pedigree` checked/reported a path, without consuming it for fitting | No pedigree-fitting module exists to benchmark or optimize. Supplied pedigree covariance is independently validated as GLS. |
| Random covariates | Accepted, warned, then ignored | Now rejected before analysis instead of producing an unintended fixed-effect analysis. Pedigree requests also fail explicitly. |
| Burden | Weighted FP64 burden, scalar reference and batched production implementation | Independent R singleton and existing multivariant/tiling/allele/missingness tests pass; shared matrix scheduling improved. |
| SKAT | Weighted projected-genotype score/Gram/eigenvalues, exact special cases, bounded Imhof, named Satterthwaite fallback | Fixed scale dependence; reuse kernel geometry across traits; symmetric Gram computation. Approximation accuracy remains a material limitation. |
| SKAT-O | Seeded shared-Gaussian minimum-p calibration, explicit simulation count | Retains its simulation-based statistical definition. Geometry and quantile work are reused, base Gaussian scores shared across rho, and cancelling burden components no longer discard other estimable components. |

Relatedness-aware burden/SKAT/SKAT-O and exact deletion after nonidentity
whitening remain unsupported. Categorical-SNP association remains disabled.
The excluded legacy `gov.nih.exon` tree is not part of the supported build and
was not brought into scope.

## Confirmed defects and fixes

1. **GLS residuals were centered in the wrong space.** If `V=LL'`, the correct
   residuals are `(I-Q Q') L^-1 y`, where Q spans `L^-1 X`. These residuals
   need not have ordinary mean zero. Calling the ordinary centered
   standardizer after projection changed the fitted model. The independent
   diagonal-GLS fixture gives effect **1.331558935361217**, while the baseline
   gave **1.303792905418955** (about 2.1% low). Whitened rows are now scaled by
   their uncentered residual norm, preserving the GLS cross-products. R checks
   cover identity, unequal repeated-subject groups, and a supplied numerator-
   relationship covariance.
2. **SKAT kernel scale was treated as rank.** The absolute `1e-12` eigenvalue
   cutoff rejected valid kernels after a common rescaling. Spectra/Gram
   matrices are now normalized before moment/eigenvalue work, with a
   dimension-relative numerical eigenvalue threshold. Public mixture inputs
   reject nonfinite and negative eigenvalues. Tests include common scales
   from `1e-100` to `1e100`. Arbitrary values whose weighted products overflow
   double precision are still outside the supported numerical range.
3. **An exactly cancelling burden could invalidate all SKAT-O components.**
   Its component is now the degenerate zero-kernel distribution (p=1), while
   the nonzero SKAT components remain usable.
4. **CUDA class initialization could bypass the discovery failure boundary.**
   Missing cuBLAS dependencies caused `ExceptionInInitializerError` and then
   repeated `NoClassDefFoundError`, rather than normal backend discovery
   failure/fallback. Native initialization now occurs inside discovery's
   guarded block. The original suite had eight native-initialization errors
   on this host before runtime staging and the fix.
5. **Matrix worker errors could return partially computed results.** Tasks
   were launched with `execute`, without inspecting their exceptions, and
   interrupts were swallowed. Futures now propagate failures; interrupts
   preserve the thread's interrupt status and abort the operation. A
   deliberately malformed worker input and an independent full scalar
   product check exercise both cases.

Cohort signatures/preparation tags and set-result checkpoint signatures are
version 2. Old affected result/preparation state must not be reused. Raw
matrix-cache formats are unchanged. FP32 remains an explicitly selected
approximation; the optimizations do not expand its scope.

## Measured optimization results

Windows 11, Intel Core i9-14900K (32 logical processors), Java 25 (Java 17
compilation target), two RTX 4090 devices. CPU module microbenchmarks use
deterministic synthetic matrices, three warmups, and seven measured calls.
The same harness runs against saved baseline classes and updated classes.
These are workload-specific medians, not whole-chromosome speedup claims.

| Workload | Baseline ms | Updated ms | Baseline / updated |
|---|---:|---:|---:|
| Fixed-effect preparation, 16 rows x 512 samples, 3 covariates | 2.1487 | 0.2815 | 7.63x |
| Burden production, 16 variants, 8 traits, 512 samples | 2.6944 | 0.8560 | 3.15x |
| SKAT production, same dimensions | 21.4314 | 2.7902 | 7.68x |
| SKAT-O production, same dimensions, rho={0,.5,1}, 99 simulations | 1186.8624 | 68.0480 | 17.44x |
| Compound-symmetry model preparation, 512 samples/256 subjects | 18.8302 | 1.9003 | 9.91x |
| Compound-symmetry whitening/projection, 16 x 512 | 2.4265 | 0.1177 | 20.62x |

The small-call timing ranges are in the evidence logs; JIT, scheduling, and GC
are visible, particularly for burden. The aggregate module checksum is
`5120.606534123168` before and after, and the cohort norm checksum is
`10522.5276075697` in both versions. Numerical tests, rather than a checksum
alone, are the correctness gate.

A separate comparison of all 16 ordered production kernel results (eight SKAT
and eight SKAT-O) retained every identifier and all eight adjusted SKAT-O
p-values exactly. Maximum absolute differences were `1.82e-12` in Q,
`6.67e-16` in p, and `5.33e-15` in log10 p. See the captured result-parity file.

Changes responsible for the improvements:

- Small matrix products execute inline. Larger calls cap workers by actual
  output rows, and routine matrix operations no longer print two debug lines.
  Arithmetic within each output row is unchanged.
- Compound symmetry uses the exact inverse square root on each subject:
  contrast directions scale by `1/sqrt(1-rho)` and the mean direction by
  `1/sqrt(1+(m-1)rho)`. This replaces dense cohort construction/factorization
  and triangular solves with linear work/storage for this covariance family.
  General supplied covariance matrices retain Cholesky.
- SKAT and SKAT-O reuse weighted kernel geometry for traits sharing the same
  set/null-design tile. Gram products use symmetry and contiguous row dots.
- SKAT-O quantile inversion caches spectrum-dependent angles/envelopes
  instead of evaluating all logarithms/arctangents at every bisection point.
  Blocks are created on demand, bounded at approximately 1 MiB per inversion.
  Exact single/equal-eigenvalue quantiles use the chi-square quantile directly.

The GPU kernels were retained. Transfer-inclusive FP64 association-product
medians from the existing benchmark are:

| Samples / square output tile | Current CUDA ms | Current OpenCL ms | Current OpenBLAS CPU ms | JDistlib 0.10.2 CUDA ms | JDistlib OpenCL ms |
|---|---:|---:|---:|---:|---:|
| 128 / 2048 | 9.746 | 9.775 | 24.873 | 20.435 | 24.801 |
| 512 / 1024 | 3.953 | 6.019 | 12.172 | 5.205 | 8.158 |
| 2048 / 512 | 3.126 | 3.159 | 9.776 | 4.499 | 8.687 |

Candidate dgemm uses the same generated matrices, dimensions, and
`1/(N-1)` normalization. Sixteen scalar cells per candidate shape agreed to
at most `1.39e-17` absolute error. The current integration suite independently
checks production FP64/FP32 products, residualization, padding, and compact
pattern finalization. Benchmarks select one device; they do not measure
multi-GPU scaling or a full disk-backed analysis.

## Independent numerical evidence and remaining limits

- `scripts/generate-audit-reference.R` generates deterministic references
  with R 4.6.1, `nlme`, and CompQuadForm 1.4.4. Fixtures are committed under
  `test/resources/audit-reference`; ordinary tests do not require R.
- Fixed, repeated-subject, and supplied pedigree-covariance GLS agree with
  R's explicit inverse-covariance projection, including effect, R-squared,
  t, DF, and log10 p. Production burden and singleton SKAT also match R.
- The 54 Student-t log-tail cases span DF 1 through 1e6 and t=0 through 1e10.
  Both JDistlib versions have the same maximum absolute log-tail discrepancy
  from R, `1.49e-8`, at a very large-magnitude log probability; relative
  tolerances are used for such values. This grid does not find a numerical
  benefit from replacing the old T routine.
- The 30 quadratic-form cases use exact chi-square reductions or Davies
  references that returned `ifault=0`, with requested accuracy `1e-7`.
  Twelve production cases use exact reductions; two report Imhof convergence;
  their maximum absolute discrepancy is `3.56e-9`. **Sixteen fall back to
  Satterthwaite, with maximum absolute discrepancy `0.0525815`.** These
  results must not be described as generally accurate SKAT tail probabilities.
- The fixed-grid quiet-block Imhof stopping rule is a heuristic, not a
  rigorous general tail-error bound. This audit has not proved that every
  declared-converged result is accurate, especially in extreme tails.
- SKAT-O retains the shared Gaussian parametric-null approximation and
  simulation floor `1/(B+1)`. It is not an analytic SKAT-O implementation and
  is not a finite-sample exact test when residual variance is estimated.
  Optimizing it does not remove these statistical limits. Kernel probabilities
  still floor underflow to `Double.MIN_VALUE`; they do not provide arbitrary
    precision log tails.
- Existing regression gates exercise exact missingness schedulers, rank/DF,
  sample reordering, MAF/MAC, reference/effect alleles, overlapping/sliding
  sets, CSV/VCF/generated BCF, cache integrity, and checkpoint/restart. They
  are bounded fixtures. No private production cohort was supplied or used.

## JLinAlg and JDistlib adoption assessment

Live GitHub release metadata was verified: JDistlib **v0.10.2** and JLinAlg
**v0.3.0**. The audit uses the published thin JLinAlg library alongside the
published JDistlib 0.10.2 all-in-one JAR on a separate evaluation classpath.
It does not modify GPU eQTL's production dependencies. The published JLinAlg
CLI contains 0.10.1; the evaluated combination explicitly substitutes 0.10.2.

Verified SHA-256:

- JLinAlg-0.3.0-library.jar: `93e027c49cc79d87f36322f9bc7a960f851732e210c55dcc4a4655d113098b8f`
- jdistlib-all-0.10.2.jar: `8b50aaa11d2cbd512525e0d74f8e609f40db9f4fc179ccb7a885a82257e0ac81`

The final CPU dependency timing run used 100 warmup calls and 11 measured
batches of ten calls. Median old/new Student-t time for 100,000 evaluations
was 11.95/18.60 ms; QR factor/solve for 512x8 was 0.106/0.125 ms; Cholesky
factor/solve for 128x128 was 0.134/0.123 ms. A full JLinAlg OLS fit took
0.194 ms and the small fitted REML example 1.36 ms. Full fitting is more work
than factor/solve, so those are not paired speedup comparisons. Timing ranges
are recorded, and these measurements provide no basis for a blanket speed claim.
The maximum normalized log-tail error from R was `3.07e-15` in the 54 cases.

| Integration | Recommendation | Evidence / constraint |
|---|---|---|
| Replace the main association GEMM | No | Current CUDA was faster on all three matched shapes; current tiling, device exclusivity, residency, and restart contracts already work. |
| Replace each association with a full JLinAlg OLS fit | No | Full model fitting does extra work and defeats reuse of a shared covariate projection. |
| Replace all QR/rank decisions now | No broad change | Coefficients agree within `9.72e-17` on the 512x8 fixture, but rank thresholds differ. Small CPU timing varies with warmup; changed rank decisions require an explicit compatibility study. |
| Add fitted Gaussian mixed/pedigree null models | Yes, as a separately designed extension | JLinAlg has REML, pedigree models, a P3D/EMMAX-style scanner, and a related-sample set-test null interface. A 40-observation/10-group REML fit converged and matched R nlme coefficients/variances within `2.78e-9`. |
| Replace SKAT probability calculations wholesale | Not yet | Published JLinAlg's positive gamma series matched 24 of 30 references within `1.22e-8`, but failed its convergence budget for all six cases with spectrum `{.01,1,10}`. It solves some current approximation gaps, but is not an unconditional drop-in replacement. |
| Upgrade only the distribution dependency | Reasonable maintenance work, not demonstrated acceleration | Used Student-t tails already agree. Modern namespace is `jdistlib.*`, versus `net.sourceforge.jdistlib.*`; this requires deliberate build/import/package integration. |

For fitted mixed effects, variance components generally depend on the trait.
Do not whiten every trait/genotype with one fitted covariance unless that is
the declared model. JLinAlg's current dense scanner explicitly retains an
N-by-N projection and constructs covariance/inverse workspaces. One FP64
5000-by-5000 matrix alone is about 200 MB. A production adapter should prepare
and dispose of null states in bounded trait tiles, preserve exact sample masks,
record convergence and DF method, and route block products through the existing
exclusive GPU contexts. Sparse pedigree fitting and fixed-null score scanning
must be benchmarked separately from dense fitting and per-marker refitting.

The next statistical priority is a reliable, error-reporting quadratic-form
tail strategy across broad spectra, followed by an explicit fitted mixed-model
mode. This audit does not silently relabel supplied-covariance GLS as REML or
replace SKAT-O's statistical definition.

## Reproduction and artifacts

The main gate is `./mvnw test` and the runnable package is built with
`./mvnw package`. On Windows use `.\mvnw.cmd`.

```powershell
# R/CompQuadForm are needed only when regenerating references.
& 'C:\Program Files\R\R-4.6.1\bin\Rscript.exe' scripts\generate-audit-reference.R
.\mvnw.cmd test
.\mvnw.cmd -DskipTests package

java -cp 'target\test-classes;target\classes;target\gpu-eqtl-2.0.0-SNAPSHOT-all.jar' gov.nih.eqtl.QModuleAuditBenchmark
java -cp 'target\test-classes;target\classes;target\gpu-eqtl-2.0.0-SNAPSHOT-all.jar' gov.nih.eqtl.QCohortAuditBenchmark
java --enable-native-access=ALL-UNNAMED -cp 'target\test-classes;target\classes;target\gpu-eqtl-2.0.0-SNAPSHOT-all.jar' gov.nih.gpu.GpuBackendBenchmark
```

For matched baseline measurements, build the stated baseline commit separately
and run the same benchmark harness with its classes preceding updated classes
on the classpath. This session saved the original compiled classes under
`target/baseline-classes` before source changes.

`scripts/QDependencyAudit.java` and `scripts/QDependencyGpuAudit.java` are
standalone candidate-comparison programs, intentionally excluded from the
production build. Compile them with the two checksum-verified candidate JARs
and the GPU eQTL JAR on the classpath. The first is in package
`org.jlinalg.settest` so it can evaluate the published internal quadratic-form
routine; that package-private method is not proposed as a supported integration
API. Commands and compact captured results are in `docs/audit-2026-09-09/`.

This host's CUDA 13 toolkit did not contain the CUDA 12 cuBLAS runtime required
by JCuda 12.6. The audit staged NVIDIA cublas 12.9.2.10, runtime 12.9.79, and
NVRTC 12.9.86 under ignored `target/cuda12`, then prepended their `bin`
directories to the test process PATH. No system driver/toolkit was replaced.
CUDA driver version is 610.88 / CUDA driver API 13.3.

The final ordinary suite has **143 tests: 138 passed, five optional skips,
zero failures/errors**, and `mvnw package` passed. The skipped tests are four
optional oneMKL checks and the externally configured bcftools fixture. CUDA
and NVIDIA OpenCL product/projection/pattern tests executed. Other GPU vendors,
other operating systems, and real multi-GPU scaling remain unmeasured.

The optional `cpu-mkl-windows-x86_64` profile subsequently ran
`CpuBackendTest,GpuKernelIntegrationTest`: **24 passed, zero skips/errors/
failures**, covering the four oneMKL checks omitted from the ordinary artifact.
The external bcftools fixture remains unavailable; generated BCF integration
tests executed in the ordinary suite. A packaged smoke run without the staged
CUDA libraries successfully fell back to NVIDIA OpenCL, and an unsupported
pedigree request exited with an explicit error. Packaged backend discovery with
the staged libraries found both RTX 4090 devices.
